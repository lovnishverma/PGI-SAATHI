Step 2 · Brand identity

A pin that is also a cross, held by a hand

One shape carries the four ideas in the brief. The map pin is navigation. The cross cut out of it is care. The cupped arc below it is a supporting hand and also the path you walk. No red, no building, no gradients.

Logo rationale and rules

What each part says

Pin: guidance, a destination. Cross cut-out: healthcare, drawn as empty space so it never reads as a red medical cross. Cupped arc: a companion's hands and the route underfoot, in teal. Rounded corners: approachable for first-time users.

Use

Clear space equals the width of the cross arm on all sides. Minimum size: 24 dp for the mark, 120 dp wide for the horizontal lockup. Below 24 dp use the mark alone. The words read exactly PGI SAATHI, with the tagline Your Companion at Every Step. in the lockups and on the splash. The tagline never sits beside the mark alone and is not used in the app header.

Do not

Do not recolor the cross, add gradients or shadows, place the mark on busy photos, add the PGIMER name, seal or logo, or add any line implying approval by an institution. Wordmark is Inter ExtraBold. Convert it to outlines before store submission.

Step 3 · Design system

Tokens, type, components

The proposed palette is kept. Where a proposed colour fails text contrast, the original stays for fills and icons and a darker text variant is added. Every change is listed below.

Colour

Changes to the proposed palette

TokenProposedNowReason

Colour usage

  • ✓Primary for the main button, headings accents, selected states, the featured card and navigation.
  • ✓Secondary teal for the logo arc, small accents and tints. Text on teal fill is not allowed (3.4:1). Teal text uses the darker variant.
  • ✓Emergency red only for emergency entry points and the “outdated” status. Never decorative.
  • ✓Status colours always travel with an icon and a word. Colour alone never carries meaning.
  • ✓Borders: light border for dividers, strong border for anything the user must find and tap (inputs, language cards), at least 3:1 against the surface.
  • ✓Product UI is light only in this iteration. Dark theme is not designed yet.

Typography

Inter for English, Noto Sans Devanagari for Hindi, Noto Sans Gurmukhi for Punjabi. Hindi and Punjabi get 8–10% more line height so matras and vowel signs are never clipped. All sizes scale with the Android font-size setting.

Spacing, radius, elevation, touch

Spacing scale (dp)

Screen margin 20 dp (16 dp under 340 dp wide). Gap between cards 12. Section gap 24–28.

Radius

Only three radii. Pills are used for the suggestion chips and nothing else.

Elevation

Level 1 · cards, fields
Level 2 · selected card, featured card, sheets
Touch targets
48 × 48 dp minimum for every control (SRS asks for 44). Buttons 56 dp tall. Bottom navigation items 64 dp tall. Language cards 88 dp tall.
Icon grid
24 dp, 1.8 dp stroke, round caps and joins, outline only. Sits in a 44 dp tinted tile in cards and lists.
Motion
Only the splash spinner. It stops under reduced-motion. No page transitions are specified yet.

Iconography direction

One outline family. Icons name the thing, not the feeling. Every icon has a visible text label next to it, so none is left to be guessed.

Component inventory

Rendered with the same CSS as the screens. Eleven reusable components are specified in this iteration.

Accessibility considerations

  • ✓Contrast. Body text on background 12.2:1. Secondary text 5.5:1. All status text at least 4.5:1. Strong borders at least 3:1.
  • ✓Not colour alone. Status chips carry icon plus word. Selected language card has a thicker border, a filled check and a tint. The active tab has a pill and bold label.
  • ✓Targets. 48 dp minimum, 56 dp for primary actions.
  • ✓Scalable text. Whole UI follows the text scale. Try 160% in the controls.
  • ✓Screen reader. Cards are buttons with the title and description as one label. Language cards are a radio group with checked state. Nav marks the current tab. Icons are hidden from the reader.
  • ✓Plain language. Short sentences, no hospital jargon in labels. “OPD” is kept because it is the term signs use.
  • ✓Language. Each screen sets its language so readers use the right voice. A three-script hint on the language screen helps people who cannot read English.
  • ✓Reduced motion. The only animation stops.

Review findings

Decisions needed before Iteration 02

  • 1Translations. Hindi and Punjabi strings are my drafts. A human reviewer must approve them (SRS FR-001).
  • 2Emergency content. The warning-sign list and any emergency number are left as placeholders because the SRS requires reviewed, verified content. Who signs this off?
  • 3Logo check. Run a trademark and similarity search before public use. Outline the wordmark for store assets.
  • 4Fonts. Bundle Inter and both Noto fonts inside the app so text renders offline.
  • 5Language card second line. The brief repeats the same word on both lines (हिंदी / हिन्दी). I kept it as written. Say if you want an English name there instead.
